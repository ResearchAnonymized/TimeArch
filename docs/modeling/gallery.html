01 — TimeArch Brownfield Discovery (wrapped process)

The main picture: what partners see outside, and the steps inside.

Clear name: TimeArch Brownfield Discovery
Technical ID: MC_timearch_brownfield (avoid saying only “Meta-composition”)
Inputs: System sources · Requested change
Outputs: Change Proposal · Build Plan · Agent Pack JSON · Case status
  • Outside = one process step
  • Inside = Import → Recover → Analyze → Human review → Package → Release

02 — Brownfield path — step by step

Full journey as a linear knowledge pipeline.

Clear name: Brownfield path
Ends with: Released / Closed case status
  • Each step consumes the previous package
  • Humans approve decisions, tests, and release

03 — Who does the work

Code workers, AI workers, and human workers.

Code (FN): Import, recover parsers, build Agent Pack
AI (AG): Map, blast-radius, critic
Human (HU): Go/No-go, release gates

04 — Human review and rework loop

How Go / No-go routes work without a hard-coded flowchart.

Go: enters Build Plan and Agent Pack
No-go: feedback re-runs Analyze (bounded retries)
Safety: agents stop unless may_implement is true

05 — One AI step in detail

Map change to architecture — role, task, rules, references → mapping.

Clear name: Map change to architecture
Input: Requested change (+ System inventory as references)
Output: Feature–architecture mapping (with parents)

06 — Nested change analysis

One wrapped step outside; coordinator + specialists inside.

Clear name: Change analysis
Technical ID: MC_change_analysis
Outside output: Draft handoff

Code, AI, and humans across the lifecycle.

Code: Locks, document assembly, package-lock
AI: Stage generators · Planner/Executor/Critic
Human: Author, architect review, Stage 15 approvers

gf-04 — Human review and package seal

Per-stage critique loop and Stage 15 seal.

Per stage: Accept / dismiss / refine → lock
Stage 15: Stakeholder approval → sealed package
Safety: 16–18 blocked until seal
