ANSE — Artifact-Driven Autonomous Software Engineering

An AI-native software engineering toolchain for autonomous development across the complete lifecycle. TimeArch provides the Software Design & Architecture capability within ANSE; KERKIS coordinates tools and artifacts underneath.

Intro Architecture Artifacts RE → Testing Quality Assurance Deployment KERKIS Feedback Ecosystem

What ANSE is

ANSE is a research toolchain for autonomous software engineering. Specialized tools cover lifecycle stages; they collaborate through explicit, versioned engineering artifacts, not only through free-form prompts. Production feedback closes a continuous evolution loop.

Artifact-driven engineering

Each stage consumes and produces typed engineering artifacts that later stages (and other tools) can verify, version, and trace.

Agents collaborate through explicit, traceable software artifacts rather than only through prompts.
Agent↓ Engineering artifact↓ Agent↓ Engineering artifact↓ Agent

Provenance, version, producer, consumer, relationships, and lifecycle stage travel with each artifact — without requiring the visitor to read a metadata schema first.

Requirements Engineering → testing

Testing begins in requirements. Initial test cases are first-class RE outputs, not an afterthought of coding.

Requirements → Acceptance criteria → Initial test cases → Implementation → Verification

Initial tests are derived from

Requirements + Standards + Regulations + Domain knowledge

Quality Assurance — lifecycle-wide verification

QA is a planned ANSE capability. It does not stop at “does the code compile?” It asks whether the implemented and deployed system satisfies original requirements and architectural decisions.

Verification graph

  • Requirements ↔ Architecture
  • Architecture ↔ Implementation
  • Implementation ↔ Tests
  • Tests ↔ Running system

Core traceability

Requirement→ Acceptance criteria→ Test case→ Implementation→ Test result

Planned QA capabilities

Unit Integration Regression End-to-end API Performance Security Architecture conformance Requirements verification

Deployment — to a running, verified system

Deployment is a planned capability. ANSE should not stop at generated source code. Implementation moves into a running environment with continued QA.

Build→ Package→ Containerize→ Configure→ Deploy→ Validate
Code→ QA→ Deploy→ Smoke / E2E→ Running system

Planned deployment capabilities

Docker Kubernetes CI/CD Cloud / hosting Infra configuration Health checks Smoke tests E2E validation Rollback

KERKIS — backbone, not a stage

KERKIS is the orchestration and integration layer under the ANSE toolchain. ANSE tools specialize; KERKIS coordinates them and the shared artifact store. See also TimeArch’s process modeling gallery and brownfield / greenfield wrapped-process docs.

Continuous feedback & change management

ANSE is not a one-shot generator. Runtime signals become change requests that re-enter requirements, architecture, code, and tests before redeployment.

Production / Runtime→ Monitoring & feedback→ Change request→ Impact analysis
Affected requirements→ Architecture→ Code→ Tests→ Redeployment

Feedback sources include user feedback, runtime failures, monitoring events, performance and security issues, quality signals, and new or changed requirements.
