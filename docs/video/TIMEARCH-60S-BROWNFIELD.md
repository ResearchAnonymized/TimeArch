## Voice-over (full read)

> Real systems aren’t blank pages. TimeArch recovers what you have, designs the change, and hands off a package coding teams can trust.
>
> Import your code. Recover the as-is architecture. Propose the change. Release only when humans approve. Then close the case.
>
> Inside Change, you see the impact, review every decision — Go, No-go, or Drop — and lock tests. You get a Change Package: stakeholder proposal, engineer build plan, and machine-ready JSON for coding agents. Agents only implement what’s allowed.
>
> Same engine powers greenfield too — but for brownfield, the promise is clear: recover the system. Decide the change. Ship a package — not a guess.

## Shot list (capture order)

Record these UI moments in a brownfield project before editing:

1. **Title / logo** — clean splash or Mode chooser (1–2s)
2. **Dashboard** — brownfield project with `N/5` progress visible
3. **Import** — GitHub URL or upload (2–3s cursor motion)
4. **Recover** — inventory / as-is Mermaid diagram
5. **Change → See changes** — impact / to-be diagram
6. **Review decisions** — click **Go** on one ADR
7. **Build guide** — acceptance / test Go state
8. **Change package** — Proposal cover → Machine record → `agent_pack.json` download
9. **Release / Closed** — gate approved or `5/5` (optional)
10. **End card** — “Import → Recover → Change” + repo/wiki URL
